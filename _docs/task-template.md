# Groomed issue template

## Goal

Describe the observable result and who benefits.

## Description

Describe the current behavior/problem, the intended workflow and relevant context. Link the product rule, design reference and dependent issues.

## Acceptance criteria

- [ ] One observable statement per required behavior.
- [ ] Boundary, failure and permission cases are explicit.
- [ ] Persistence/concurrency behavior is explicit where relevant.

## Out of scope

List deferred work with real links to its follow-up issues. Do not silently drop requirements.

## Constraints

State the current iteration, service/API boundary, permitted files, selected libraries and required checks.

## Verification handoff

Engineer: candidate commit, implementation summary, commands actually run and results. Leave open.

QA: tested commit, verdict for each criterion, actual commands and results, browser/manual reproduction when applicable. Close only after PASS.
